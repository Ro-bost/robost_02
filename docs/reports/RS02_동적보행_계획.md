# RS02 동적 보행: 계획 → 검증 → 수정 → 실행

## 목표 수정

2026-09-22 사용자 목표 확인: **20cm 성공은 필수 조건이 아니다. 목적은 보행 가능한 범위와 한계 원인 확인이다.**
앞으로 성공할 때까지 높이별 정책을 바꾸는 실험과, 같은 정책으로 한계를 측정하는 실험을 분리한다.
기존 완주 결과와 실패 로그는 보존한다. 아래 이전 완주 개발 계획보다 이 목표를 우선한다.

이전 crawl은 발 하나씩 지지 확인 후 이동하는 저속 동작 시험이다. 15cm 코스 699초 완주는
‘잘 걷는다’의 합격 근거로 사용하지 않는다. 기존 PPT도 동적 보행 결과 발표용으로 사용하지 않는다.

## 1. 계획

공개 mjlab의 Go1 속도 추종 MDP(관측·보상·종료·PPO 학습 구조)를 RS02에 적용한다.
Go1 정책 가중치를 그대로 쓰는 것이 아니라 RS02의 질량·관성·기구·구동 한계에서 다시 학습한다.
프레임워크: https://github.com/mujocolab/mjlab
고정 커밋: `27577db821fe321c819072a851bdda234b89f32d` (Apache-2.0).
PPO는 RSL-RL 구현을 사용한다. ROS/외부 유료 GPU/클라우드 로그 업로드는 사용하지 않는다.
기존 `rs02-mujoco`와 분리한 conda `rs02-rl`을 사용한다.

### 제안된 공학적 통과 기준 — 공인 규격 아님

먼저 평지에서 초기조건을 바꾼 10회 × 30초 시험을 실시한다.
0.25 및 0.50m/s 각각에 대해 첫 3초 이후를 평가한다.

- 전도·리셋·몸통 지면 지지 없이 10/10 생존
- 전방 속도 RMSE ≤ 0.10m/s, 평균 속도 오차 ≤ 명령의 20%
- 몸통 roll/pitch RMS ≤ 8도, 최대 ≤ 20도
- 선 자세 정지 → 보행 → 정지 → 재출발 응답을 별도 평가
- 접촉 중 발 미끄러짐, 발 들림 높이, 좌우 대칭·접촉 주기를 기록하여 끌기/점프 편법 판별
- 모터 토크·속도 제한 유지, 지속 포화율·정격 초과·관절 한계·비발 접촉 별도 보고
- 1배속 영상을 직접 검토. 시간 단축 재생을 보행 품질 증거로 쓰지 않음

계단은 평지 통과 후 낮은 단차부터 학습하고, 최종 평가는 기존 깊이30cm·폭1.6m,
5칸 상승→1m 평지→5칸 하강의 15/20cm 고정 코스에서 수행한다.
우선 목표는 전진 연속 통과이며 후진이나 중간 정지로 통과하면 별도 전략으로 표시한다.
계단 속도 목표는0.15m/s부터 평가하되 성공률과 실제 평균·최저 속도를 공개한다.
실행 전에 기준을 정하고 결과가 나쁘다고 기준을 낮추지 않는다.

## 2. 검증

학습 전 MJCF의 질량16.940606kg,12개 관절,기존 관절범위,관절 토크17/17/25.2Nm를 비교한다.
정지 PD와 무작위 입력에서 유한값·구동 제한·센서/관측 차원을 확인한다.
RS02 실제 메시와 관성은 보존한다. 시각 메시만 빼서 GPU를 빠르게 학습할 때도 관성과 충돌형상은 유지한다.
새 환경은 비발-지형 접촉 및 자체 충돌을 활성화하고 기록한다.
센서 높이지도는 이상적인 시뮬레이션 정보이며 실물 센서 검증은 별도다.

## 3. 수정

RS02 모델 어댑터와 관절 PD/동작 스케일만 별도 파일에서 설정한다.
Go1 질량·다리 길이·토크값은 그대로 가져오지 않는다.
성능이 나쁘면 보상/제어 주기/PD/초기자세를 수정하고 동일 평가 기준으로 재시험한다.
발을 강제로 놓거나 몸통을 끌어주는 외력, 물리 중 qpos 변경은 금지한다.
학습 에피소드 초기화는 허용하되 평가는 자동 리셋으로 실패를 숨기지 않는다.

## 4. 실행 및 판정

작은 병렬 환경으로 smoke test → GPU 처리량 확인 → 제한된 1차 학습 → 독립 평가 순서다.
학습 보상 상승, 학습 시작, 체크포인트 생성은 보행 성공과 다르다.
실패 로그도 보존하고 통과 여부는 별도 평가 JSON으로 남긴다.
실제4절링크·열·토크속도 곡선·통신지연이 보정되기 전에는 실물 하드웨어 승인하지 않는다.

## 5. 2026-09-22 반복 평가 프로토콜

완주 판정의 구현 오류(네 발 동시 착지 요구/출구 평지까지 계단 측면으로 취급)를 수정했다.
새 v2 정의와 이전 기록 감사는 `RS02_계단_개선_실험.md`에 공개한다. 원본 결과는 보존한다.
개별 발 출구 착지, 모든 발 출구 통과 후2초 생존, 무리셋, 계단 측면 우회 금지를 요구한다.

중간 정책을 탐색 시험에서 선택한 뒤, **체크포인트·명령0.25m/s·최대40초를 고정**하고
각 높이에서 seed42/43/44를 별도 프로세스로2회씩 실행한다. 실패를 빼고 성공률을 계산하지 않는다.
같은 seed의 반복은 수치 민감도를 확인하는 것으로, 독립적인 실물 환경6개를 뜻하지 않는다.
탐색 시험과 고정 후보의 반복 시험 성공률은 합쳐서 유리하게 표시하지 않는다.
완주와 접촉/관절/모터 품질, 실물 하드웨어 안전 판정은 별개다.

## 6. 한계 평가 계획 — 아직 실행 결과가 아님

1. 15cm 반복 검증에 사용한 rhythm500을 기준 정책으로 고정한다. 높이별 자동 정책 선택은 쓰지 않는다.
2. 우선 속도0.25m/s,발판 깊이0.30m,폭1.6m,5단 상승/1m 평지/5단 하강,
   초기조건과 종료 기준을 고정하고 높이만 변화시킨다. 낮은 높이부터20cm까지 비교한다.
3. 성공/실패가 달라지는 구간은 더 촘촘하게 시험한다. 관측된 성공률이 높이에 대해 단조롭다고 가정하지 않는다.
4. 높이 시험과 별도로 속도를 한 변수씩 바꾼다. 실패 시험을 빼거나 실패한 높이에서 정책을 교체하지 않는다.
5. 완주율 외에 정체/낙상/비발 접촉/관절 여유/토크 포화/미끄러짐/정격 대비 RMS를 함께 보고한다.
   완주했더라도 과도한 접촉이나 구동 부담이 있으면 안전 운용 범위에 포함했다고 말하지 않는다.
6. 먼저 얻는 것은 **현재 제어기와 시뮬레이션 모델의 운용 범위**다. 제어 실패만으로 하드웨어 불가능을 단정하지 않는다.
   경계의 실패 원인은 기구학적 도달 범위,구동 여유,접촉/마찰,제어 문제로 구분해 별도로 진단한다.
7. 필요한 경우 같은 실패 조건에서 다른 제어기로 비교하되 별도 진단 결과로 표시한다.
   토크·관절 범위·충돌을 유리하게 변경해 한계를 숨기지 않는다.

실제 토크-속도 곡선,열/연속 정격,4절 링크 비선형 전달비,센서·구동 지연이 미검증이므로
현재 기록으로 실물의 최대 계단 높이를 확정할 수 없다.20cm가 실패해도 유효한 시험 결과로 남긴다.
