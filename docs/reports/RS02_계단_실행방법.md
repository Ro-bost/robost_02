# RS02 계단 실행 방법 — 2026-09-22 최종 선택 후보

> 목표 정정:20cm 성공 자체는 필수 조건이 아니며,보행 한계와 실패 원인을 확인하는 것이 목적이다.
> 기본 launcher는 높이에 따라 **서로 다른 정책**을 선택하므로 아래 표는 완주 시연 결과다.
> 하드웨어 한계 비교에는 그대로 사용하지 않고,정책·속도·코스 조건을 고정한 별도 평가가 필요하다.
> 계획은 `RS02_동적보행_계획.md`의6절을 참고한다.기존 결과는 변경하지 않았다.

## 확인된 결과

> 현재 기본 실행은 rhythm 정책이다. 과거 clean_v2의3/3 이후 재실행 실패,
> support/route 후보의 반복 실패까지 모두 `RS02_계단_개선_실험.md`에 보존했다.
> 아래 결과는 새로 고정한 후보의 반복 시험이며, 실물 안전 인증은 아니다.

0.25m/s 명령, 초기조건 seed42/43/44를 별도 프로세스로2회씩 실행하여 높이별6/6 완주했다.
코스는15cm 또는20cm의5단 상승→1m 평지→5단 하강이다. 발판 깊이0.3m, 폭1.6m이다.
각 발이 출구 바닥에 착지하고, 모든 발이x>4.30m를 지난 뒤2초 더 생존해야 완주다.
리셋·낙상·몸통/상부다리 지면 접촉·관절 한계±0.005rad 초과·3초 정체·계단 옆 우회는 실패다.
네 발의 동시 착지는 요구하지 않는다. 스윙이 있는 보행을 위한 판정 v2다.

| 높이 | 체크포인트 | 반복 완주 | 완주 시간 |
|---|---|---:|---:|
| 15cm | `stairs_rhythm_v1/model_500.pt` | 6/6 | 24.02~26.70초 |
| 20cm | `stairs_rhythm_v1/model_1000.pt` | 6/6 | 24.66~26.00초 |

정책은 명목 물리·정확한 상태 관측에서 학습했고, 실행에서는 무작위 행동을 사용하지 않는다.
세 seed는 초기 위치/방향이 조금 다르다. 같은 seed 반복은 수치 민감도 확인이며 실물6대 시험은 아니다.
표의 통과율은 이 제한된 명목 조건의 표본 결과다. 다른 속도·마찰·센서 오차에 대한 보장은 아니다.

**완주와 하드웨어 안전 통과는 다르다.** 채택 후보의 반복 시험은 관절 범위를 지켰으나
종아리 접촉이 남는다. 50Hz 측정 접촉 비율은15cm8.7~14.3%,20cm15.1~16.6%다.
모터 환산 RMS는 최대 약10.8Nm로 제공 문서의 정격6Nm보다 높다.
열·토크-속도·실제4절 링크·센서/구동 지연까지 검증하지 않았다. 실물에 바로 실행하지 않는다.

## 창을 열어 실제 시뮬레이션 실행

```bash
cd /home/bang/robost
conda activate rs02-rl

# 15cm
uv run --no-project --python "$CONDA_PREFIX/bin/python" run_rs02_stairs.py \
  --stairs-cm 15 --speed 0.25

# 20cm
uv run --no-project --python "$CONDA_PREFIX/bin/python" run_rs02_stairs.py \
  --stairs-cm 20 --speed 0.25
```

`--speed`만 바꾸면 전진 속도 명령을 변경할 수 있다. 검증된 기본값은0.25m/s이다.
더 느리게 설정한다고 반드시 더 안전하거나 잘 걷는 것은 아니다. 변경한 속도는 아래 방법으로 다시 평가한다.
계단 높이를 선택하면 해당 높이에서 검증한 체크포인트를 자동으로 불러온다.
다른 정책은 `--checkpoint 경로 --adapter gait|support|route|rhythm`을 함께 지정한다.
같은 입력 크기여도 제어 설정이 다르므로 어댑터를 혼용하지 않는다. 최신 체크포인트가 항상 더 좋지는 않다.

GUI는 넘어지면 초기화할 수 있으므로, 계속 움직이는 화면만 보고 통과라고 판단하지 않는다.
`--play-seconds 3`을 붙이면3초만 실행한다. 새 rhythm20cm GUI 경로의 실행·정상 종료도 확인했다.
정지 자세 확인용 `run_rs02_mujoco.py`와 보행 실행용 `run_rs02_stairs.py`는 서로 다르다.

## 실패를 숨기지 않는 평가와1배속 영상 저장

```bash
uv run --no-project --python "$CONDA_PREFIX/bin/python" run_rs02_stairs.py \
  --stairs-cm 20 --speed 0.25 --headless --seed 42 --duration 40
```

출력은 `output/rl/user_stairs20_날짜_시간/`에 자동 생성한다.

- `evaluation.json`: 완주 여부/시점, 첫 실패, 관절·접촉·속도 수치
- `evaluation_1x.mp4`: 실제 계산된 물리 궤적의1배속 영상
- `qpos_env0.npy`, `scene.mjb`: 원본 상태 기록/물리 모델
- `evaluator_source.py`, `policy_adapter_source.py`: 평가 시작 당시 코드

`course_completed`는 코스 완주 지표다. `numerical_gate_pass`는 평지 기준을 계단 인증으로
오인하지 않도록 계단 평가에서는false로 유지된다. `hardware_pass=null`은 하드웨어 미검증을 뜻한다.

## 이미 저장된 대표 영상

- 15cm: `output/rl/rhythm500_repeat/h15_seed42_repeat0/evaluation_1x.mp4`
- 20cm: `output/rl/rhythm1000_repeat20/h20_seed42_repeat0/evaluation_1x.mp4`
- 반복 원본: `output/rl/rhythm500_repeat/summary.json` (15cm와 이전20cm4/6 포함),
  `output/rl/rhythm1000_repeat20/summary.json` (선택20cm6/6)
- 학습 종료 후 launcher 재현: `output/rl/final_launcher15`, `output/rl/final_launcher20`

## 직접 반복 평가

```bash
uv run --no-project --python "$CONDA_PREFIX/bin/python" evaluate_rs02_stairs_matrix.py \
  --adapter rhythm --checkpoint output/rl/stairs_rhythm_v1/model_1000.pt \
  --heights 20 --seeds 42 43 44 --repeats 2 --speed 0.25 \
  --output output/rl/my_repeat20
```

출력 폴더는 새 이름을 사용한다. 모든 실패/성공과 원본 로그를 남기고 실패한 시험을 제외하지 않는다.
영상은 `render_rs02_trial.py 평가폴더`, 측정 그림은 `plot_rs02_trial.py 평가폴더`로 만들 수 있다.

설계와 실패→수정 과정은 `RS02_계단_개선_실험.md`에 기록했다.
