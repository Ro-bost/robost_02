## 1. GUI와 PNG가 달랐던 정확한 원인

사용자가 보낸 화면에서 넓은 회색 판으로 보인 부분은 URDF의 **충돌 박스**였다.
기존 `run_rs02_mujoco.py`는 PNG 생성 때만 충돌 도형을 숨겼고, GUI는 기본 표시 옵션으로
열었다. GUI는 물리 시간도 자동 진행시켜, 관절을 제어하지 않은 모델의 자세가 변할 수 있었다.
이전 답변에서 이를 자세·재질 차이만으로 설명한 것은 충분하지 않았다.

현재는 충돌 박스를 group 3으로 명시적으로 분류하고, GUI/PNG 모두 동일한 표시 옵션과
카메라를 사용한다. 기본 자세는 `stand`다. `launch_passive()` 미리보기에서는 물리 시간을
진행하지 않아 오른쪽 PNG와 같은 자세가 유지된다. 실제 데스크톱 창을 열어 확인했고,
2초 GUI 자동 종료 시험도 정상 종료 코드 0으로 통과했다.

보행용 모델도 visual mesh는 보이고 충돌 박스는 숨겨진다. 충돌 계산 자체는 계속 수행된다.

## 3. 구현한 MPC

기본 centroidal(로봇 전체를 하나의 강체로 근사) MPC를 OSQP로 구현했다.
MuJoCo는 물리 시뮬레이션을 맡고, `rs02_mpc.py`가 매번 최적화와 모터 제어를 수행한다.
별도의 학습된 정책이나 MuJoCo에 내장된 보행 제어기를 가져온 것은 아니다.

| 항목 | 설정 |
|---|---|
| 상태 | 위치 3, roll/pitch/yaw 3, 선속도 3, 각속도 3 = 12차원 |
| 제어 입력 | 네 발의 x/y/z 지면 반력 = 12차원 |
| 예측 구간 | 10스텝 × 0.04초 = 0.4초 |
| 최적화 주기 | 약 25 Hz |
| 물리/발 제어 주기 | 500 Hz, dt=0.002초 |
| 비용 | 목표 위치·속도·자세 오차와 힘 크기 최소화 |
| 제약 | 마찰 피라미드 μ=0.65, 발 수직 반력 0~160 N, 공중 발 반력 0 |
| 적용 방식 | 예측한 힘 중 첫 시점만 적용한 뒤 새 상태로 재최적화 |
| 관절 제어 | 발 위치/속도 제어 + MPC 힘의 Jacobian 전치 매핑 + 관절 중력항 |
| 모터 토크 제한 | hip/thigh ±17 N·m, knee ±25.2 N·m |
| MPC 관성 근사 | 대각 관성 [0.23, 0.65, 0.72] kg·m² |

실제 MuJoCo 동역학에는 URDF에서 가져온 링크별 질량·관성을 쓴다. MPC 내부의 단일
강체 관성은 조정용 근사치다. Euler 각 선형화와 현재 발 위치를 예측 구간 내에서 고정하는
근사도 포함한다. 토크 한계는 최적화 이후 모터 명령에 적용하므로 토크 포화가 발생할 수 있다.

트롯은 `FR + RL`, `FL + RR` 대각선 쌍이 번갈아 움직인다. 평지는 주기 0.65초/
접지 비율 0.65, 계단은 0.9초/0.72로 설정해 양쪽 쌍이 함께 지지하는 구간을 둔다.
시작 1.5초 동안 자세를 안정시킨 뒤, 1.5초에 걸쳐 명령 속도를 올린다.

몸통은 free joint로 움직이며, 초기화 이후 qpos를 덮어쓰거나 몸통 외력을 넣지 않는다.
12개 모터와 지면 접촉으로만 전진한다.

## 7. 적용 범위

이 제어기는 알려진 지형에서의 기본 MPC 데모다. 이전 계단 시험에서 약 12.8 cm의 옆 방향 편차와
최대 12.8°의 roll이 남아 있어 정밀한 경로 추종은 추가 개선 대상이다.
URDF의 단순 collision box와 무릎 4절 링크 등가화는 그대로 사용한다. 자기 충돌은
패키지의 초기 설정 권고대로 끄고, 로봇-지형 충돌은 켰다.

실제 모터의 발열·토크-속도 곡선은 모델링하지 않았다. 관절 속도 최대값은 저장하며
이번 시험에서는 URDF 속도 한계 아래였지만, 속도 제한을 별도 강제하는 제어기는 아니다.
현재 검증 범위는 평지 전진과 계단 **오르기**다.
