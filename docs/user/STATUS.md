# 진행상황 · 2026-09-23 정리 기준

프로젝트 목적은 현재 제어기와 RS02 모델에서 보행 가능한 범위와 실패 원인을 확인하는 것이다.
현재는 높이별 선택 정책으로 계단 완주를 시연한 단계이며, 같은 정책의 연속 높이 한계 시험은 미완료다.

| 구분 | 확인된 내용 | 근거 |
|---|---|---|
| 15cm 시연 | rhythm500, 0.25m/s, 6/6 완주, 24.02~26.70초 | [반복 원본 요약](../reports/evidence/rhythm500_repeat/summary.json)의 15cm 6개 |
| 20cm 시연 | rhythm1000, 0.25m/s, 6/6 완주, 24.66~26.00초 | [반복 원본 요약](../reports/evidence/rhythm1000_repeat20/summary.json) |
| 동일 정책 비교 | rhythm500의 20cm는 4/6 완주 | 위 rhythm500 요약의 20cm 6개 |
| 이전 crawl | 15cm 약 699초 완주, 20cm 하강 중 실패 | [WALK 보고서](../reports/WALK_검증_보고서.md) |
| 하드웨어 안전 | 미검증 | 종아리 접촉, 정격 초과 RMS, 열·지연·4절 링크 미검증 |
| GitHub 업로드 | `Ro-bost/robost_02`의 `main`과 v0.1.0 Release에 소스·정책 업로드 | [배포 안내](DEPLOY.md) |
| 파일 정리 | 코드·문서·모델·테스트 분리 및 배포 도구 추가 | [정리 기록](ORGANIZATION.md) |

두 높이의 6/6은 서로 다른 정책 결과다. 세 초기조건 seed를 각각 두 번 실행한 명목 조건 표본이며,
실물 환경 6개의 독립 시험 또는 모든 조건의 성공률로 해석하지 않는다.
rhythm500 요약의 전체 10/12를 15cm 성공률로 사용하지 않는다.

현재 정책은 종아리 접촉이 남고 모터 환산 RMS 최대 약 10.8Nm가 문서 정격 6Nm보다 높다.
완주와 실물 운용 승인은 구분한다. `hardware_pass=null`은 미검증이다.
수치는 기존 보고서와 저장 JSON을 정리한 것이며 이번 파일 정리에서 전체 계단 시험을 새로 수행한 결과가 아니다.

다음 연구 순서는 [기존 계획 6절](../reports/RS02_동적보행_계획.md)에 따른다.

1. rhythm500과 속도·마찰·코스·판정을 고정하고 높이만 변화시킨다.
2. 현재 CLI의 높이 선택은 15/20cm만 지원하므로 더 낮은 높이 시험에 앞서 지형 생성과 판정을 함께 확장·검증한다.
3. 성공/실패 경계에서 정체·접촉·관절 여유·토크·미끄러짐 원인을 분리한다.
4. 속도 변화는 별도 시험으로 진행한다. 실패 높이에서 정책을 바꾼 결과는 진단 결과로 구분한다.
5. 열·토크-속도·4절 링크·센서 및 구동 지연을 보정한 뒤 실물 가능 범위를 논의한다.
